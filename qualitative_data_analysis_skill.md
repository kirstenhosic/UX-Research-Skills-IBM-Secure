# Merged into `analyze_your_data.md`

This file used to be the strict, integrity-first qualitative analysis
path, alongside a standard path in `analyze_your_data.md`. There is now
one analysis scenario, and it is `analyze_your_data.md`.

**Nothing was dropped.** The hard rules, the data-integrity audit, the
red-flag list, and the per-finding rigor checks are all in the merged
file, and they apply on every study rather than on the ones where
somebody chose this file.

The split asked the researcher to decide, before the analysis started,
whether they suspected hallucinated data, confirmation bias, or
cherry-picking in their own work. That is the one thing nobody can
self-diagnose, and the person least able to is the novice this suite is
written for. The audit now scales on facts about the study instead —
destination, whether a hypothesis was held going in, whether the
researcher attended the sessions, whether the analysis is from
transcripts or from memory.

It also never bought a stricter outcome. `research-synthesis-checker`
and `research-significance-checker` escalate on an incomplete corpus, on
"we focused on the most interesting sessions," and on analysis done from
memory, whichever file produced the findings. The strict path bought an
earlier warning, given only to the people who already knew to ask for it.

This stub is here so existing links and pasted configs fail loudly
instead of silently. It can be deleted once nobody is pointing at it.
